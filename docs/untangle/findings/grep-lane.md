# Area: grep-lane (ss-grep JS path + Rust lane)

## 1. Map
- Entry: agent runs `ss-grep` -> native CLI (crates/sweet-search-cli/src/agent_tools.rs) -> (a) daemon native lane
  (crates/sweet-search-native/src/lane/*, thread in the daemon, socket `<sock>.grep`), or on decline (b) POST /agent-tool ->
  core/agent-tools/daemon-route.js:53 / cli.js:38 dynamic-import `eval/agent-read-workflows/bin/_ss-helpers.mjs` -> `runAgentTool`.
- `_ss-helpers.mjs` (2106 lines) holds ONE function `runAgentTool` (l.142-2036, 48 nested fns) with cmdGrep/cmdFind/cmdRead/cmdSemantic/cmdTrace.
  It lives in `eval/` but ships (package.json `files` l.94-96) and is the product ss-* implementation.
- cmdGrep (l.~690-1070) parses args (`_ss-argparse.mjs`), calls `queryWarmSearch` (-> core/search/search-server.js `queryServer` -> HTTP /search ->
  sweet-search.js -> `bareGrep`) and falls back to `s.bareGrep` directly in a `catch`. It then renders with grep-output-shaping.js + agent-output-fixes.js.
- `bareGrep` (core/search/search-pattern.js:278-520): refresh pins -> outside-scope probe -> `generateRegexMatches` (planner) -> BRE dialect retry ->
  unindexed fallback -> epoch retry -> sort/cap -> diversity (`applyGrepFileDiversity`) -> results -> line classes -> family manifest -> sibling line.
- Back ends under the planner: native sparse-gram (infrastructure/native-sparse-gram.js), literal prefilter (search-pattern-prefilter.js),
  sparse delta overlay (search-pattern-sparse-overlay.js), ripgrep fallback (search-pattern-ripgrep.js), chunk mapping (search-pattern-chunks.js).
- Rust: `crates/ss-grep-core` (args, globs, literals, classes, shaping, render, enrich, paths, chain, collate) = pure ports with
  `// Mirrors:` markers (199 hits; all JS targets resolve, checked by script). `crates/sweet-search-native/src/lane` = gate, pipeline (cmdGrep),
  baregrep (bareGrep), engine (planner), overlay, graph (SQLite via bridge), state, server.
- The lane is 4 weeks old (first commit 2026-10-13). Since then 10 JS commits touched these files, so the parity burden is untested by churn.

- One option object for the whole grep pipeline: a single `GrepRequest` module (parse once, defaults once) shared by the HTTP layer, bareGrep and the CLI, so renames at 4 hops and the `FIX` -> `allocOpts` -> `bodyOpts` shuffle disappear.

- Move the ss-* implementation out of `eval/` into `core/agent-tools/` (or `core/cli/`), split `runAgentTool` into one module per subcommand with an exported render function, so cmdGrep's 4 output paths become one render pipeline that the lane mirrors once.
