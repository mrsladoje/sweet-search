## Behavior questions
1. `hardware-capability.js:187` uses the first addon candidate only. With the loader fallback, a CUDA addon that fails to load would give the CPU addon's answer (probably `available:false`) instead of `null`, which can change `cudaReason` text and `config/embedding.js:224` `parallelLateInteraction`. Accept the new result?
2. Removing the old-addon guards in `native-sparse-gram.js` (see item 5) turns a stale prebuilt addon (JS newer than the `.node`) from "falls back" into a thrown error. Is a stale addon a case to keep supporting?
3. `core/incremental-indexing/infrastructure/hashing.mjs:205` loads `crates/sweet-search-native/index.js` by relative path; `crates/` is not in `package.json` `files` (only `crates/wasm-router/pkg/`), so an installed package never finds it and uses `@node-rs/xxhash` (or the pure-JS xxh64) instead. Nothing was run to compare the hex output of those backends. If they differ, hashes depend on the install type. Move to `loadNativeAddon` (an installed package then uses the platform addon)?
4. `CASCADE_CONFIG.enabled` is `process.env.SWEET_SEARCH_CASCADE_ENABLED === 'true'` (`config/ranking.js:113`), while `model-registry.js` downloads the cross-encoder for `1|true|on|yes`. `SWEET_SEARCH_CASCADE_ENABLED=1` downloads the model but leaves the cascade off. Same family: seven off-switches accept `0|false|off` but not `no` (`env-flag.js isOffValue` accepts `no`). Move all to `isOnValue` / `isOffValue`? Behavior changes only for values `1`, `on`, `yes`, `no`.
5. `platform.js:165` reads `<SWEET_SEARCH_DATA_DIR>/config.json` for `allowRuntimeModelDownload`; `init-config.js` always reads `.sweet-search/config.json`. With `SWEET_SEARCH_DATA_DIR` set, the two read different files. Which one is right?

Not reported (checked, still fine or not fixable inside the constraints): native addon load blocks in `native-rescore.js`, `native-inference.js`, `simd-distance.js`, `binary-hnsw-index.js` are now one `loadNativeAddon` call each with its own validate (the per-module cache is a one-line pattern, not worth a wrapper); `graph-search.js` `find*` engine is still called from `sweet-search.js:1019-1022` (needs the owner: it answers a different question set than ss-trace); `warmCache` in `graph-search.js:536` and `warmGraphDbCache` in `db-utils.js:183` have no caller (left to the unused-identifier pass); per-language tables in `core/graph` (`call-site-scanner.js` already uses a plan object; `type-usage-scanner.js`, `receiver-types.js` branches carry different regexes per language, a table would not be shorter and the JS-family set `{javascript,typescript,tsx}` appears 4 times with the same members but each in a different local shape); SQL table names in 11 graph modules (reads for their own features; a single store module is a large move, no cheap slice remains after `code-graph-visibility.js`); `PROJECT_ROOT` frozen at import in `platform.js` (documented in `mcp/server-main.js`; needs F3 project identity first); `TraceOutputSchema` in `mcp/trace-tool.js` is outside this area.

Nothing else worth fixing in this area.
