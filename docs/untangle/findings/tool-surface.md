# tool-surface findings (READ-ONLY survey)

## 1. Map
- The six agent tools (`ss-search|grep|find|read|semantic|trace`) have ONE implementation: `runAgentTool()` in `eval/agent-read-workflows/bin/_ss-helpers.mjs` (2106 lines; the whole module body from line 143 to ~2037 is ONE function, closed by `} // runAgentTool`). It is written as a CLI script (process.env / cwd / stdout / process.exit) and hosted by `core/agent-tools/virtual-process.js` (AsyncLocalStorage shim).
- Routes to it:
  1. `bin/ss-*` (4-line node stubs) -> `core/agent-tools/launch.js` -> spawns the native Rust binary (argv0 = tool name) or falls to `cli.js`.
  2. After `link-native-tools.js` the stub IS the Rust binary: `crates/sweet-search-cli/src/agent_tools.rs` `run()` -> (ss-grep only) native lane socket `<sock>.grep` -> POST `/agent-tool` (`core/agent-tools/daemon-route.js` inside `search-server.js`) -> `runAgentTool` with `host.getSearcher`. On 404/409/503 or no daemon -> `node core/agent-tools/cli.js` (JS fallback) -> same `runAgentTool`.
  3. `eval/agent-read-workflows/bin/ss-*` (bash) -> source `_ss-env.sh` -> exec `bin/ss-*` (route 1/2).
  4. `sweet-search` CLI: `core/cli.js` (JS dispatcher) -> native `sweet-search` (`crates/sweet-search-cli/src/main.rs`, 3248 lines) -> its OWN GET routes `/search`, `/read?`, `/trace?`, `/read-semantic?` on the daemon, or JS fallbacks `search-cli.js`, `search-read.js`, `search-trace.js`, `search-read-semantic.js`. This is a second, separate implementation of read/trace/semantic from the ss-* tools.
  5. MCP: `mcp/server.js` -> `server-main.js` (8 tools: search, trace, index, health, repo-map, vocab-prewarm, read, read-semantic) -> `tool-handlers.js` / `read-tool.js` / `trace-tool.js`, in-process `getWarmSearcher()`; a third implementation of search/read/trace shaping. No grep/find in MCP.
- Daemon: `core/start-server.js` / `core/cli.js --serve` / `search-cli.js --serve` -> `search-server.js` (2198 lines; `startServer()` ~line 758-1716 is one ~960-line function). Daemon lifecycle satellites: `daemon-registry.js`, `daemon-starts.js`, `daemon-heap.js`, `daemon-log.js`, `wsl-keepalive.js`, `server-identity.js` (socket/pid path), `grep-lane.js` (JS side of the Rust lane).
- Spawners of the daemon: Rust `spawn_daemon` (main.rs:1553), JS `autoSpawnServer` (search-server.js:2135), SessionStart hook `session-daemon-prewarm.mjs` (~line 280), `ensureDaemonForProjectRoot`.
- Entry points: package.json `bin` (sweet-search, sweet-search-mcp, sweet-search-hook, 6 ss-*), Rust `main()` dispatch on argv0 (main.rs:2118), `core/start-server.js`.
- Callers: harnesses (Claude Code, Codex, opencode) via shell; MCP clients; SessionStart hook; eval/ and scripts/ via `_ss-helpers.mjs` (eval imports it, and product core/agent-tools imports it back).
