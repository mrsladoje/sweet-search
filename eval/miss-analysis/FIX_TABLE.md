## What we deliberately did NOT recommend (and why)

- **Broad embedding-text tweaks (`embedText` variant changes).** No miss in our trace pointed at a deterministic text-construction bug; JS/Ruby gap is suspicious but needs a chunk-by-chunk audit before any embedding change.
- **Docstring/signature embedding revisits.** The cand-gen misses we saw are queries that are uninformative *by themselves* (e.g. `"int->None"`, `"Copyright IBM Corp."`); they are not symptomatic of an embedding-side regression.
- **Graph expansion policy changes (1hop/2hop/none switches).** Until the real-repo indexes are rebuilt with current pipeline so cascade runs (#2), any expansion-policy claim is unfalsifiable — current data shows 0 rescues either way.
- **Production graphExpand default flips.** Mode B vs mode A produced identical Recall@10, so flipping `graphExpand` default in production is currently neither beneficial nor harmful per this evidence.
- **Cascade `gateThreshold`/`ceTopK` tuning.** Cascade is disabled on the validated graph indexes; cannot tune what didn't run.
