\section{Reproducibility}\label{sec:repro}

Everything is in the repository~\cite{sweetsearch_repo} under \texttt{eval/benchmarks/hnsw-rivals/paper}: the harness, the
adapters, the declared grids, the plans, the frozen operating points, the analysis scripts and two freeze records
(\texttt{FREEZE.json} for the main study, tag \texttt{hnsw-rivals-freeze-2026-10-17-v2}; \texttt{REPFREEZE.json} for the
replication, commits in \S\ref{sec:replication}). The release adds the vectors of every set and model, the splits, the
ground truth, every held-out record with its retained lists, and the per-job timing files.

\paragraph{One entry point.} \texttt{reproduce.sh DATA RESULTS REPDEV REPHO POST} checks both freeze records, runs every
analysis script in order and builds this PDF:

\begin{small}\begin{verbatim}
bash reproduce.sh DATA RESULTS REPDEV REPHO POST
\end{verbatim}\end{small}

\noindent It needs only the released files and a Python environment from the pinned lock file; it reruns no
timing. \texttt{check\_complete.py} confirms that every planned held-out job has a complete record (\nm{hojobs} jobs of
the main study on the three AWS CPUs).

\paragraph{Adding a system.} A new system needs one adapter with the common interface (\texttt{adapters/common.h}:
build, load, search, and return vector ids with scores), its build and search grids in \texttt{grid.py}, and a run of
the dev plans; the selection and analysis scripts need no change. The FAISS adapters
(\texttt{adapters/faiss\_adapters.cpp}) are the worked example.

\paragraph{Rerunning timings.} \texttt{aws/} holds the launch and run scripts for the cloud machines (account values in
a file that is not in the repository), and \texttt{make\_local\_plans.py} makes plans for one local machine.
