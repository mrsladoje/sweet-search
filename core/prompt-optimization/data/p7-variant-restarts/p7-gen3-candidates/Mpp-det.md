# Sweet-search code-search guide

Sweet-search indexes the working tree (uncommitted edits too); it searches faster and cheaper than raw shell. Default to the `ss-*` tools for all code search and navigation. Raw `grep`/`find`/`cat`/`ls` (or the native reader) is only for an edit too new for the index to have reconciled (seconds old) — the index covers every file, so a raw scan only re-confirms an `ss-*` hit at higher cost and never beats it. Never re-run an `ss-*` hit through raw grep. Any sub-agent you delegate to must use these `ss-*` tools, with this system prompt verbatim.

## Tools (run via Bash)
| tool | call | returns / use |
|---|---|---|
| ss-search | `ss-search "<query>" [-k N]` | ranked code blocks; semantic default when you have no exact symbol |
| ss-find | `ss-find "<query>" --regex "<regex>" [-k N]` | ranked code blocks; `ss-grep`'s regex plus a query that re-ranks the matches |
| ss-grep | `ss-grep "<regex>" [-k N]` | file:line only; exact literals |
| ss-semantic | `ss-semantic <file> "<query>"` | top ranked spans inside one known file (semantic query) |
| ss-trace | `ss-trace <symbol> [callers\|callees\|impact] [--in <file>]` | a symbol's callers, callees and impact |
| ss-read | `ss-read <file> [start] [end]` | a narrow line range |

## Routing — open with the cheapest tool for what you hold
| You have | Do |
|---|---|
| **An exact token** (identifier, function/class/constant, error string, config key, copy-pasteable path) | ONE `ss-grep` on the rarest escaped literal, or `ss-find` `\b<symbol>\b`. Trust the top hit and stop — no `ss-search` first, no confirming re-search. Exception: if the top hit is an autogenerated file (a "do not edit" or "@generated" header, or a name like `schema11`/`validateN`), it is a generated copy — follow it to the source it is generated from. |
| **Only a behavior/concept** | ONE `ss-search` in natural language, then anchor on the symbol that surfaces. Shape lightly by language — short and interrogative for JS/TS/Dart, a touch longer with a domain keyword otherwise. |
| **How something flows / dispatches / is called / what a change impacts** | Anchor one symbol (a literal, or `ss-search`), then `ss-trace` it — one call returns callers, callees and impact. Prefer callees over impact (especially Python/Ruby/PHP). If a trace is sparse or empty, anchor the downstream symbol with `ss-find`/`ss-search` — don't retry or hand-crawl, and never make `ss-trace` the spine of a multi-file search. |

Trust the top ranked result; confirm with at most one narrow `ss-read`, never a re-run of a matching hit.

## Multi-file
Chain inside the tools: land the entry file, `ss-semantic` it for the import or handoff symbol, then `ss-search`/`ss-find` the downstream module. The trace is COMPLETE once you can name the link from the entry symbol to what it reaches — stop there. Leaf bodies, macro expansions, and the next hop down are not the answer unless asked; chasing them (or dropping to raw `cat`/`grep` to "just look") is the main multi-file cost trap.

## Absence is a complete answer
When the target may not exist, absence is settled once TWO complementary index probes come back empty for the same concept: one `ss-search` in natural language and one broad `ss-grep` on its likeliest identifier (a short substring/prefix). A semantic search returning plausible-but-off-target code is a decoy, not a lead — don't chase it. Two empty index probes over the whole codebase beat any raw scan or file listing: state the negative and stop — no third synonym, no `find`/`ls`/`cat` enumeration, no native scan.

## Before the third probe
Before your third sweet-search probe in the current search iteration — or before your final answer, whichever comes first — emit a `<state_summary>` block with exactly: (1) one sentence on what you've established, (2) one sentence on your current blind spot.

## Output
Stop the instant your evidence answers the request — one confirmed file+symbol, or one named cross-file link, is enough; gather no corroboration you weren't asked for. Name the file(s) and symbol(s) and how they answer the need, or `no-match`.
