# Sweet-search: Code Navigation and Search Protocol

Sweet-search provides a high-performance index of the working tree, including uncommitted changes. Use the `ss-*` toolset for all navigation and search tasks. Avoid native shell commands (`grep`, `find`, `cat`, `ls`) or native readers unless an edit is mere seconds old and not yet indexed; otherwise, raw scans are redundant, costly, and inferior to the index. Never re-run an `ss-*` result using raw `grep`. Any sub-agents must adhere to these rules and use these tools exclusively.

## Tool Reference
*   `ss-search "<query>" [-k N]`: Semantic search; use when no exact symbol is known.
*   `ss-find "<query>" --regex "<regex>" [-k N]`: Regex-based search with semantic re-ranking.
*   `ss-grep "<regex>" [-k N]`: Exact literal search.
*   `ss-semantic <file> "<query>"`: Returns top-ranked spans within a specific file.
*   `ss-trace <symbol> [callers|callees|impact] [--in <file>]`: Maps symbol relationships.
*   `ss-read <file> [start] [end]`: Retrieves a specific code range.

## Search Strategy
*   **Exact Tokens**: Use `ss-grep` (for literals) or `ss-find` (using `\b<symbol>\b`). Trust the top result immediately. If the top hit is an autogenerated file (e.g., `@generated` header or `schema`/`validate` naming), ignore it and locate the source of generation.
*   **Concepts/Behaviors**: Use one `ss-search` with a natural language query. Anchor on the resulting symbol. Keep queries short and interrogative for JS/TS/Dart, or add domain keywords for other languages.
*   **Flow/Impact**: Anchor a symbol via `ss-search` or literal, then use `ss-trace`. Prefer `callees` over `impact` (especially for Python/Ruby/PHP). If `ss-trace` is empty, switch to `ss-find`/`ss-search` for the downstream symbol; do not use `ss-trace` as the primary method for multi-file traversal.

## Multi-file Navigation
Chain tools: identify the entry file, use `ss-semantic` to find the import/handoff, then use `ss-search`/`ss-find` for the downstream module. Stop once the link between the entry symbol and the target is identified. Do not chase macro expansions or leaf bodies unless explicitly requested; avoid raw `cat`/`grep` "exploration" to prevent cost traps.

## Handling Absence
If a target may not exist, absence is confirmed only after two empty, complementary index probes: one `ss-search` (natural language) and one broad `ss-grep` (likely identifier). Ignore semantic results that are merely "plausible" but off-target. If both probes return empty, conclude the search with `no-match`. Do not perform raw scans or file listings.

## State Reporting
Before your third `ss-*` probe in any search iteration, or before providing your final answer, output a `<state_summary>` block containing:
1. One sentence summarizing established facts.
2. One sentence identifying your current blind spot.

## Final Output
Stop immediately upon finding the answer. Provide the file(s), symbol(s), and an explanation of how they satisfy the request. If the target is not found, output `no-match`. Do not gather unrequested corroboration.
