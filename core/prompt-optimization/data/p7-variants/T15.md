# Sweet-search — code search tool guide

Sweet-search provides index-backed code search tools. Prefer them over raw grep/ripgrep and blind file reads for any code search, navigation, or discovery — they are faster and semantic. Fall back to plain grep/read only for changes not yet indexed (e.g. uncommitted edits) or when these tools return nothing. After every empty or clearly-irrelevant tool result, produce a structured `<failure_analysis>` block before the next call — this forces explicit hypothesis revision and activates test-time compute even in non-reasoning mode.

## Core rule: failure_analysis before backtracking
When a tool call returns empty or clearly irrelevant results:
```
<failure_analysis>
hypothesis: <what you expected to find and why>
why_it_failed: <concrete reason — wrong regex anchor, symbol not in this file, query too broad, file not indexed yet, …>
revised_hypothesis: <updated belief about where the answer lives>
next_action: <the specific tool call and shaped query you will use next>
</failure_analysis>
```
Do NOT skip this when a result is empty, and do NOT proceed without completing it.

## Query shaping — by family
### [[ss-search]]
- **C-family (C / C++ / Zig):** medium interrogative (9–15 tokens), symbol verbatim.
- **JS-mobile (JS / TS / Dart):** short interrogative (4–8 tokens), symbol verbatim.
- **Default:** medium declarative (9–15 tokens), symbol verbatim + domain keyword.
### [[ss-find]]
Word-bounded regex `\b<symbol>\b`; query short imperative + symbol (4–8 tokens), e.g. "find <Symbol> usage".
### [[ss-semantic]]
Query with the symbol alone (≤3 tokens); only after a file is confirmed. If empty on the identified file, emit `<failure_analysis>` before trying [[ss-grep]] on it.
### [[ss-trace]]
Pass the symbol verbatim (never an NL question) for callers, callees, and impact; add `--in <file>` when ambiguous. In Python/Ruby/PHP, prefer callers/callees over impact — impact is unreliable there.

## Routing flow with backtracking
```
# routing policy pseudocode — NOT executable code
attempt: [[ss-search]] with family-conditioned shape
if empty: emit <failure_analysis> → [[ss-find]] with \b<symbol>\b
if empty: emit <failure_analysis> → [[ss-grep]] with \b<symbol>\b
if still empty: emit <failure_analysis> → report [[no-match]] with all blocks inline (absence verified)
if any attempt succeeds: [[ss-semantic]] for span confirmation → [[ss-trace]] if call graph needed
```
Each `<failure_analysis>` must change the approach (anchor, scope, or tool) — never repeat a near-identical query.

## Multi-file flow with backtracking
When an import-chain hop returns empty:
1. Emit `<failure_analysis>` noting the broken link.
2. [[ss-grep]] the repo for the downstream symbol.
3. If found, resume the chain; otherwise report [[no-match]] for that hop.

## Behavioral queries
1. [[ss-search]] with a behaviour-describing phrase.
2. If empty: `<failure_analysis>` + retry with a symbol-only query.
3. [[ss-trace]] for call paths once the entry symbol is confirmed.
4. [[ss-read]] for runtime evidence.

## Stateful summary rule
Before your 3rd tool call (or before your final answer, whichever comes first), you MUST output a `<state_summary>` block containing exactly: (1) one sentence summarising what you've established so far, (2) one sentence stating your current blind spot or open question.

## Output
Respond in [[agent-format]]. Report [[expectedFiles]], [[expectedSymbols]], [[expectedFacts]]. For no-match outcomes, include all `<failure_analysis>` blocks inline so the caller can audit the chain.
