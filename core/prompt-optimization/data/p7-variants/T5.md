# Sweet-search — code search tool guide

Sweet-search provides index-backed code search tools. Prefer them over raw grep/ripgrep and blind file reads for code search and navigation — they are faster and semantic. Fall back to plain grep/read only for changes not yet indexed (e.g. uncommitted edits) or when these tools return nothing. Shape the query by language family before routing.

## Calling the tools
Invoke via the shell (Bash). `[[ss-search]]`/`[[ss-find]]` return ranked code blocks inline; `[[ss-grep]]` is file:line only:
- [[ss-search]] → `ss-search "<query>" [-k N]`
- [[ss-find]] → `ss-find "<query>" --regex "<regex>" [-k N]`
- [[ss-semantic]] → `ss-semantic <file> "<query>"`
- [[ss-trace]] → `ss-trace <symbol> [--in <file>]`
- [[ss-grep]] → `ss-grep "<regex>" [-k N]`
- [[ss-read]] → `ss-read <file> [start] [end]`

## [[ss-search]] family-conditioned shaping
Detect the target file's language family from its extension:
- **C-family (C, C++, Zig):** medium interrogative query (9–15 tokens) containing the symbol verbatim.
- **JS-mobile (JS, TS, Dart):** short interrogative query (4–8 tokens) containing the symbol verbatim.
- **Default (all others):** medium declarative query (9–15 tokens) containing the symbol verbatim plus a domain keyword.

When the symbol is known, include it verbatim — symbol-anchored queries recall markedly better. If the target symbol or file is unknown, lead with domain terms (Default shaping) and switch to symbol-anchored shaping once a candidate symbol appears.

## [[ss-find]] family-conditioned shaping
- **JS-mobile:** definition-anchored regex `\b<keyword>\s+<symbol>\b` (language keyword + symbol); query short interrogative + symbol (4–8 tokens).
- **Default:** word-bounded regex `\b<symbol>\b`; query short imperative + symbol (4–8 tokens), e.g. "find <Symbol> usage".

Don't broaden the regex without a symbol anchor — it adds false-positive noise.

## [[ss-semantic]] shaping
Query with the symbol alone (≤3 tokens); for C-family use a short interrogative (4–8 tokens) with the symbol. Use only after a file is identified — not as a first call.

## [[ss-trace]]
Pass the symbol verbatim (never an NL question) for callers, callees, and impact in one call. In Python/Ruby/PHP, prefer callers/callees over impact — impact is unreliable there.

## [[ss-grep]] and [[ss-read]]
[[ss-grep]] for exact literal regex; [[ss-read]] to confirm or expand a file.

## Routing flow
1. Shape the [[ss-search]] query per family; call [[ss-search]].
2. If the result is file-only, follow with [[ss-semantic]].
3. If [[ss-search]] underperforms, use [[ss-find]] with the family regex.
4. If structural context is needed, use [[ss-trace]] with the confirmed symbol.
5. [[ss-grep]] as last resort for exact literals.

## Stopping
Stop once evidence is confirmed. If an attempt fails, change approach rather than repeating a near-identical query. Conclude [[no-match]] only after verifying absence (a symbol search and a broad [[ss-grep]] both empty).

## Output
Report the file(s), symbol(s), and key facts, or [[no-match]].
