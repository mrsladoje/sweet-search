# Sweet-search — code search tool guide

Sweet-search provides index-backed code search tools. Prefer them over raw grep/ripgrep and blind file reads for any code search, navigation, or discovery — they are faster and semantic. Fall back to plain grep/read only for changes not yet indexed (e.g. uncommitted edits) or when these tools return nothing. Shape the query before selecting a tool; the shaped query determines the first call. Handle no-match, multi-file flows, and behavioral queries.

## Calling the tools
Invoke via the shell (Bash). `[[ss-search]]`/`[[ss-find]]` return ranked code blocks inline; `[[ss-grep]]` is file:line only:
- [[ss-search]] → `ss-search "<query>" [-k N]`
- [[ss-find]] → `ss-find "<query>" --regex "<regex>" [-k N]`
- [[ss-semantic]] → `ss-semantic <file> "<query>"`
- [[ss-trace]] → `ss-trace <symbol> [--in <file>]`
- [[ss-grep]] → `ss-grep "<regex>" [-k N]`
- [[ss-read]] → `ss-read <file> [start] [end]`

## §1 [[ss-search]] shaping — by family
Determine language family from the file extension:

| Family | Languages | Query shape |
|--------|-----------|-------------|
| C-family | C (.c/.h), C++ (.cc/.cpp/.hpp), Zig (.zig) | medium interrogative (9–15 tokens), symbol verbatim |
| JS-mobile | JS (.js), TS (.ts/.tsx), Dart (.dart) | short interrogative (4–8 tokens), symbol verbatim |
| Default | Java, C#, Kotlin, Go, Rust, Python, Ruby, PHP, … | medium declarative (9–15 tokens), symbol verbatim + domain keyword |

**Symbol-lean alternative:** when the symbol is known, querying with the symbol alone (≤3 tokens) is also effective. When the symbol is known, include it; keep queries under ~15 tokens and avoid long NL paragraphs. If the target symbol or file is unknown, lead with domain terms (Default shaping) and switch to symbol-anchored shaping once a candidate symbol appears.

## §2 [[ss-find]] shaping — by family
| Family | Regex + query |
|--------|---------------|
| JS-mobile | definition-anchored `\b<keyword>\s+<symbol>\b`; short interrogative + symbol (4–8 tokens) |
| Default | word-bounded `\b<symbol>\b`; short imperative + symbol (4–8 tokens), e.g. "find <Symbol> usage" |

**Alternation alternative:** `\b(<symbol>|<sibling1>|<sibling2>)\b` — symbol plus two related identifiers — when you want to catch siblings.

## §3 [[ss-semantic]] shaping
Query with the symbol alone (≤3 tokens); for C-family use a short interrogative (4–8 tokens) with the symbol. Use ONLY after a file is identified — supply the file path. Not a first call.

## §4 [[ss-trace]]
Pass the symbol verbatim (never an NL question) for callers, callees, and impact in one call; add `--in <file>` when ambiguous across files. In Python/Ruby/PHP, prefer callers/callees over impact — impact is unreliable there.

## §5 Multi-file flow
When [[ss-search]] surfaces an import/delegation chain:
1. [[ss-semantic]] on the entry file to find the import or re-export.
2. [[ss-search]] / [[ss-find]] (family-shaped) on the downstream module.
3. [[ss-read]] to confirm the downstream span.
Follow the chain only while each hop yields progress.

## §6 Behavioral queries
Ask HOW, not WHERE:
1. [[ss-search]] with a phrase describing the behaviour (not just the symbol).
2. [[ss-trace]] on the entry symbol for call paths.
3. [[ss-read]] for runtime evidence.
Don't route behavioral queries to [[ss-semantic]] first.

## §7 No-match
Conclude [[no-match]] only after verifying absence: [[ss-search]] with the canonical shape, then [[ss-grep]] with `\b<symbol>\b`. For a conceptual query with no obvious symbol, first try 2–3 likely lexical anchors or a broad [[ss-search]]; only conclude [[no-match]] after those also come up empty. If both empty, report [[no-match]] with a justification. Never on a single empty result; if your query may have been wrong, revise and retry first.

## §8 [[ss-grep]] and [[ss-read]]
[[ss-grep]] for exact literal patterns or broad sweeps; [[ss-read]] to confirm a file or read a returned path.

## Stopping
Stop once evidence is confirmed; don't over-search for completeness. If an attempt fails, change approach rather than repeating a near-identical query.
