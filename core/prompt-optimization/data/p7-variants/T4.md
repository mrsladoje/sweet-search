# Sweet-search — code search tool guide

Sweet-search provides index-backed code search tools. Prefer them over raw grep/ripgrep and blind file reads for code search and navigation — they are faster and semantic. Fall back to plain grep only for unindexed changes, or when these tools return nothing. Shape the query for symbol recall before choosing a tool. Report findings in [[agent-format]].

## Calling the tools
These are CLI tools — invoke them via the shell (Bash):
- [[ss-search]] → `ss-search "<query>" [-k N]`
- [[ss-find]] → `ss-find "<query>" --regex "<regex>" [-k N]`
- [[ss-semantic]] → `ss-semantic <file> "<query>"`
- [[ss-trace]] → `ss-trace <symbol> [--in <file>]`
- [[ss-grep]] → `ss-grep "<regex>" [-k N]`
- [[ss-read]] → `ss-read <file> [start] [end]`

## Shape before routing

- **[[ss-search]]:** when the symbol is known, query with the symbol alone (≤3 tokens); when it is not, lead with domain terms.
- **[[ss-find]]:** word-bounded regex `\b<symbol>\b`; query short imperative + symbol (4–8 tokens), e.g. "find <Symbol> usage".
- **[[ss-semantic]]:** query with the symbol alone (≤3 tokens).
- **[[ss-trace]]:** pass the symbol verbatim (never an NL question) for callers, callees, and impact in one call.

## Routing after shaping

1. Start with [[ss-search]] using the shaped query.
2. If the top result is a file without a span, follow with [[ss-semantic]] on it.
3. If NL retrieval misses, switch to [[ss-find]] with the word-bounded regex.
4. Use [[ss-trace]] when callers/callees are needed and the symbol is confirmed.
5. Use [[ss-grep]] for exact literals; [[ss-read]] to confirm a file.

## Stopping
Stop once evidence is confirmed. If an attempt fails, change approach rather than repeating a near-identical query. Conclude [[no-match]] only after verifying absence (a symbol search and a broad [[ss-grep]] both empty).
