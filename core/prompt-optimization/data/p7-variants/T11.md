# Sweet-search — code search tool guide

Sweet-search provides index-backed code search tools. Prefer them over raw grep/ripgrep and blind file reads for any code search, navigation, or discovery — they are faster and semantic. Fall back to plain grep/read only for changes not yet indexed (e.g. uncommitted edits) or when these tools return nothing. Combine tool-routing discipline with evidence-backed reporting: every reported result must be supported by a tool call this session.

## Calling the tools
Invoke via the shell (Bash). `[[ss-search]]`/`[[ss-find]]` return ranked code blocks inline; `[[ss-grep]]` is file:line only:
- [[ss-search]] → `ss-search "<query>" [-k N]`
- [[ss-find]] → `ss-find "<query>" --regex "<regex>" [-k N]`
- [[ss-semantic]] → `ss-semantic <file> "<query>"`
- [[ss-trace]] → `ss-trace <symbol> [--in <file>]`
- [[ss-grep]] → `ss-grep "<regex>" [-k N]`
- [[ss-read]] → `ss-read <file> [start] [end]`

## Tool routing
### [[ss-search]] — default entry point
First call for NL queries: medium declarative query (9–15 tokens) containing the symbol verbatim plus a domain keyword. If no symbol is known yet, lead with domain terms and switch to symbol-anchored tools once a candidate appears. Validate the returned snippet.
### [[ss-find]] — symbol-exact pattern search
When [[ss-search]] returns a file-only hit or the symbol is unambiguous: word-bounded regex `\b<symbol>\b`; query short imperative + symbol (4–8 tokens), e.g. "find <Symbol> usage".
### [[ss-semantic]] — span extraction
Query with the symbol alone (≤3 tokens). Only after a file is confirmed; never a first call.
### [[ss-trace]] — call-graph evidence
Pass the symbol verbatim (never an NL question) for callers, callees, and impact; add `--in <file>` when ambiguous. Use only after confirming the symbol via [[ss-search]] or [[ss-find]]. In Python/Ruby/PHP, prefer callers/callees over impact — impact is unreliable there.
### [[ss-grep]] and [[ss-read]]
[[ss-grep]] for exact literal patterns; [[ss-read]] to verify content and collect evidence.

## Evidence discipline
1. Verify the snippet contains the target before marking it confirmed.
2. Never assert [[expectedFiles]], [[expectedSymbols]], or [[expectedFacts]] from prior knowledge.
3. A shorter confirmed answer beats a longer speculative chain.
4. Stop after evidence is complete.

## Routing flow
1. [[ss-search]] → verify → if file-only, follow with [[ss-semantic]].
2. If empty, [[ss-find]] → verify.
3. If symbol confirmed and call graph needed, [[ss-trace]] → verify.
4. [[ss-grep]] as literal fallback; [[ss-read]] to confirm at any step.

## Stopping
Stop once evidence is confirmed. If an attempt fails, change approach rather than repeating a near-identical query. Conclude [[no-match]] only after verifying absence (a symbol search and a broad [[ss-grep]] both empty).

## Output
Respond in [[agent-format]]. Report [[expectedFiles]], [[expectedSymbols]], [[expectedFacts]] — each backed by a tool result — or [[no-match]].
