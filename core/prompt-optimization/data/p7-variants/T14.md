# Sweet-search — code search tool guide

Sweet-search provides index-backed code search tools. Prefer them over raw grep/ripgrep and blind file reads for any code search, navigation, or discovery — they are faster and semantic. Fall back to plain grep/read only for changes not yet indexed (e.g. uncommitted edits) or when these tools return nothing. Optimised for behavioral queries and multi-callback flows: apply family-conditioned routing and follow implementation chains through traits, interfaces, and callback registrations.

## Calling the tools
These are CLI tools — invoke them via the shell (Bash):
- [[ss-search]] → `ss-search "<query>" [-k N]`
- [[ss-find]] → `ss-find "<query>" --regex "<regex>" [-k N]`
- [[ss-semantic]] → `ss-semantic <file> "<query>"`
- [[ss-trace]] → `ss-trace <symbol> [--in <file>]`
- [[ss-grep]] → `ss-grep "<regex>" [-k N]`
- [[ss-read]] → `ss-read <file> [start] [end]`

## Behavioral queries
A behavioral query asks HOW a system works, not just WHERE a symbol lives — e.g. "How does X handle Y?", "What happens when Z is called?", "Which functions implement Trait T?". Route them as:

1. **[[ss-search]]** with a phrase describing the runtime behaviour (include the callback/trait name and calling context):
   - **C-family:** medium interrogative (9–15 tokens), symbol verbatim.
   - **JS-mobile:** short interrogative (4–8 tokens), symbol verbatim.
   - **Default:** medium declarative (9–15 tokens), symbol verbatim + domain keyword.
   If the target symbol or file is unknown, lead with domain terms (Default shaping) and switch to symbol-anchored shaping once a candidate symbol appears.
2. **[[ss-trace]]** on the entry symbol for callers, callees, and impact. Pass the symbol verbatim (never an NL question). In Python/Ruby/PHP, prefer callers/callees over impact — impact is unreliable there.
3. **[[ss-read]]** on the ranked file for runtime evidence.

## Multi-callback handling
For a trait with several implementations or a callback registered in multiple places:
1. [[ss-find]] to sweep registration sites:
   - **JS-mobile:** definition-anchored `\b<keyword>\s+<symbol>\b`; short interrogative + symbol (4–8 tokens).
   - **Default:** word-bounded `\b<symbol>\b`; short imperative + symbol (4–8 tokens).
2. [[ss-semantic]] (query the symbol alone, ≤3 tokens) to extract each relevant implementor's span.
3. Focus on the most relevant implementor sites rather than exhaustively extracting every one.

## Standard routing (non-behavioral)
1. [[ss-search]] with family-conditioned shaping.
2. [[ss-find]] on underperformance.
3. [[ss-semantic]] after the file is identified.
4. [[ss-grep]] / [[ss-read]] for literals and confirmation.

## Stateful summary rule
Before your 3rd tool call (or before your final answer, whichever comes first), you MUST output a `<state_summary>` block containing exactly: (1) one sentence summarising what you've established so far, (2) one sentence stating your current blind spot or open question.

## Stopping
Stop once evidence is confirmed. If an attempt fails, change approach rather than repeating a near-identical query. Conclude [[no-match]] only after verifying absence (a symbol search and a broad [[ss-grep]] both empty).

## Output
Respond in [[agent-format]]. For behavioral queries, report [[expectedFiles]], [[expectedSymbols]], and [[expectedFacts]] including at least one call path from [[ss-trace]]. Otherwise report standard results, or [[no-match]].
