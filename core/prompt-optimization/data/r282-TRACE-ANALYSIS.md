# r282 trace analysis — where the money goes (final tuning, 2026-10-01)

**Conclusion.** The bill is decided by the fixed prefix and by how the provider caches it, not by
the ss-* tool output. The prefix is 44–73% of cost in every cell and arm; all tool results together
are 9–52%. Two of the three "sweet costs more" results in r282 come from caching mechanics:

1. **opencode (DeepSeek +55%, Sol +6.8%): a bench artifact.** The runner wrote the sweet rules file
   into a random per-rollout temp folder, and opencode prints `Instructions from: <absolute path>`
   into the system prompt. The provider prefix cache therefore broke on every sweet rollout. The
   shipped product uses a stable project path (`.opencode/sweet-search.md`). Fixed in the runner
   behind `SS_BENCH_STABLE_RULES_PATH=1`.
2. **Claude Code (Opus +22%): a product placement issue.** The rules file is injected as a reminder
   in the first user message, after the cache marker, so ~1.4k rule tokens are re-written to the
   cache (1.25× input price; 2× under the real 1h TTL) on every rollout: 60% of the Opus gap. The
   other 43% is tool results that are 2.4× larger per call than native `grep`/`sed`.

Everything below is dev data (the r282 pool became DEV with `r282-RESULTS.md`).

- The sweet prefix is 1.0–1.7k tokens larger than native in every cell except Sonnet (where the lean
  harness replaces a 27k-char stock prompt with a 7k-char one). The difference is the rules text
  (~1.5k tokens).
- **DeepSeek:** with the prefix cached like native, the recomputed sweet − native gap is +1.5%

  larger tool results +$0.66 (43%); cold start of the arm +$0.18 (12%); fewer turns −$0.10 reads,
  less output −$0.13.
- **Write basis:** Claude Code 2.1.281 writes with the 1h TTL; its own ledger prices writes at 2×,
  not the 1.25× the runner uses. At 2×, Opus is +28.3% and Sonnet +5.4% (CI excludes 0). Both bases
  should be quoted.
- Prefix byte-stability: stable within every rollout in every harness (all consecutive requests
  read the full earlier context, except provider-side misses on Sol).

Rank usage ("used" = the rank's file is read later or its file + symbol appear in the answer; a
lenient rule). Full tables per cell in `common-tables.md`.

| 6+ (summary) | 22 | 3 | 19 |

Composition of ss-search output (chars): code 59–70%, rank headers 12–15%, summary lines 6–8%, line
gutter 0–8% (per harness), related/same-file/continuation 5–7%, header + trailer 5%, imports 2%.
Summary entries repeat their own header line and often repeat a span or symbol shown above.

Answer to "do we need code for #2 and #3": the rank-2/3 preview bodies are used in 14–53% of calls,
and a pointer-only tail was tried before without a cost win (TRIED-LEVERS.md). ss-search results are
7–13% of cost, so the whole preview tail is worth at most ~2–4% of cost.

## 6. Follow-up after each tool (rule-based; path overlap with the next request)

- ss-grep: drill-down 22–82% (it is used as a locator), retry 0–26%.
- ss-search: "sufficient" (answer next) 23–53%; "switch" (next call is another ss-* tool that does
  not name a returned path, usually an `ss-grep` of a symbol) 29–33%; the rule cannot see symbol
  follow-ups, so "switch" overstates misses.
- ss-read: sufficient 45–79%.
- native grep: retry 45% (DeepSeek), i.e. native search chains are longer.

## 7. Reasoning and output

Reasoning is small everywhere except DeepSeek (11.6–12.9% of cost in both arms). Claude Code
thinking is 2–4% of Opus output (API `thinking_tokens`). After an ss-* result, DeepSeek reasons ~45
tokens; after a native `read`, 63 (native) / 132 (sweet). Not a lever.

## 8. Useful-content drop in Claude Code (−21% Sonnet, −37% Opus)

A measurement effect, not lost information: reads with a line-number gutter score 0.43–0.48 in every
arm (native `Read` 0.442 = sweet `ss-read` 0.435), plain `sed -n` reads score 0.78–0.83. Native Opus
read plain text in 88/130 questions, sweet in 0/130; that explains ~85% of the Opus gap. Likely cause
(unproven): the USD judge must quote verbatim spans, which cannot match lines prefixed by `NNN<TAB>`.
Checking it needs a re-judge (judge spend) — owner decision.
